Selection & reply shapes

划词之后给什么，以及怎么知道它要改写

浮条按选区能不能编辑分两套按钮。改写还是其他任务不靠关键词猜：先用两件确定的事（选区能不能改、点的是哪个按钮），只有你自己打字时才交给模型。

选中文字后浮条上的按钮

选区在哪按钮点了之后
只读内容
文章 · 收到的邮件		 问 Pie · 解释 · 翻译 · 引用 问 Pie 打开浮层并带上选区，光标停在输入框等你打字；解释 / 翻译 打开浮层直接发送，结果是一段普通回答；引用 沿用现在的行为。这四种都改写不了原文。
可编辑区域
输入框 · 在写的邮件 · 评论框		 问 Pie · 改写 · 翻译 · 更正式 改写、翻译直接发送，结果是「原文 / 改写」对比卡，带替换原文；对比卡下面就是下一轮的快捷追问，不用打字。
  • 按钮只有四个：不放「总结」（选区通常很短，要总结整页就用问 Pie）、不放「搜索 / 复制」（浏览器右键菜单已经有）。
  • 不出现浮条：密码框；设置里关了，或在「⋯」里选了「在此网站不显示」；Google Docs 这类 canvas 编辑器本来就没有普通文字选区。
  • 翻译方向：选中的不是界面语言就译成界面语言，是界面语言就译成英文。

怎么区分「改写」和其他任务

三层判断，越往前越确定。原型里「发出去 / 归档」这类词触发执行只是演示桩，产品里不靠关键词。

第几层信号为什么可靠
1. 选区能不能编辑注入脚本直接判断「输入框 / 文本域 / 可编辑区」这是页面结构的事实，不是猜测。只读选区永远不会出现「替换原文」。
2. 点的是哪个按钮浮条上的「改写 / 翻译」意图是用户显式点的，直接产出对比卡。
3. 模型怎么回可编辑选区多给一个 propose_rewrite 工具，界面看它用了哪种回法（见下表）自己打字时意图本来就模糊，让模型用「工具」表态，界面照着渲染，比解析自然语言稳。

你自己打字时，同一句话的三种结果

舞台上方「模型怎么回」三个按钮就是这三种。界面上没有「改写模式」开关。

模型怎么回浮层里显示成能替换原文吗
propose_rewrite对比卡，带「替换原文」能
直接回文字普通回答不能，只能复制
调点击 / 输入 / 跳转这类页面工具转执行，浮层收成右下角胶囊（复用现有的读 / 写工具分类 getToolClass）不涉及
文字 + propose_rewrite 都有一段说明 + 一张对比卡能
  • 为什么用工具而不是从回复里抠文字：替换原文会把文字原样写进网页，必须是干净的结果。模型的回复常带「好的，改写如下：」，从里面抠不可靠；工具参数就是要写回的那段文字本身。
  • 谁来写页面：propose_rewrite 本身不改页面，属于读类工具。真正写入是你点「替换原文」那一下——先核对原文没被改过，再用浏览器的插入文字命令写进去，这样编辑器自带的撤销（⌘Z）还能用，页面框架也能感知到内容变了。
  • 为什么不要确认弹窗：写入是你亲手点的，所以不加确认层，和 Pie 现在「工具调用不加确认层」一致。写回不可靠的编辑器就只给「复制」。

Multi-turn

多轮对话怎么在浮层里长出来

浮层不是一问一答。它和侧栏共用同一份会话历史，能在浮层里完成的就留在浮层；对话变长、需要看完整过程时，一键转到侧栏。

  • 布局：第一次只有一个输入框；发出后问题变成第一条消息，输入框移到底部。对话往下长，到最大高度后在内部滚动，新消息自动滚到底。
  • 位置：有选区时贴在选区下方 14px，不盖住原文，替换后的变化能直接看到；下方空间不足 280px 就改到顶部居中。没有选区时顶部居中。
  • 上下文：「当前页」每一轮都带；选区只属于发起它的那一轮。关掉浮层、重新选中文字再唤起，新选区挂到下一轮，用高亮的标签标出来。
  • 改写与替换：改写类回答同时给出「原文」和「改写」。「替换原文」= 把改写写回网页，替换你选中的那段文字；鼠标移到按钮上，页面会标出将被替换的部分。只有最新一条改写带这个按钮。
  • 撤销：每次替换都在对话里留一条记录，最近一次可以撤销。之后 Pie 如果已经替你操作过页面（比如发出了邮件），就不再提供撤销。
  • 原文被改过：替换前核对页面上的原文，对不上就不替换，按钮降级成「复制」，并提示「原文已经变化」。
  • 什么时候收成胶囊：只有 Pie 自己决定操作页面时才收（点击、输入、跳转）。用户点「替换原文」是一次确定的写入，不收胶囊。
  • 变长：超过 6 轮，较早的轮次折叠成一行「较早的 N 轮」，点开就地展开；要看完整过程就转侧栏，侧栏里不折叠。
  • 关闭与恢复：Esc 或点浮层外关闭，对话保留。同一标签页 30 分钟内再唤起，回到上次对话并插入时间分隔线；换了标签页或超时，就开新对话。
  • 浮条与浮层：浮条只在没有浮层时出现；浮层一打开，浮条就收起来，免得两个东西同时盖住页面。
  • 新对话：标题栏「＋」或 ⌘K，与侧栏一致（⌘N 被 Chrome 占用，网页拦不住）。

对话里会出现的消息

消息什么时候出现样式
用户消息每次发送右对齐浅底气泡；这一轮附带的选区写在气泡下方。
回答问答、总结、解释左对齐正文，不加气泡。
改写对比模型调了 propose_rewrite，或点了浮条上的改写「原文」划线、「改写」浅绿底，下面是「替换原文 / 复制」。
替换记录点了「替换原文」居中细线 + ✓；最近一次带「撤销」。
执行卡需要 Pie 操作页面虚线框，说明已转到后台执行；浮层随后收成胶囊。
结果卡任务结束或被停止绿色边框 + 步骤清单；停止时没做的步骤划掉。
时间分隔线隔一段时间后恢复居中小字，说明隔了多久、发生了什么。

Entry points

五个入口，两层结构

轻入口负责「随手拉出来」，重界面负责「看清过程和结果」。侧栏不废，降级为任务驾驶舱。

入口层级行为
⌘⇧K / Ctrl+Shift+K主入口任意网页唤起浮层；再按一次关闭。30 分钟内在同一标签页重开，回到上次对话。默认键位需在 mac / Windows 实机确认不与输入法、Spotlight 冲突。
划词浮条主入口选中文字后出现四个按钮，按选区能不能编辑分两套（见下一节）；点按钮直接带上选区发送，浮层贴在选区下方。
地址栏 pie␣补充普通页面唤起浮层并发送；新标签页放不进浮层，整页打开 Pie。
工具栏图标不变照旧打开侧栏；如果浮层里有对话，侧栏直接显示这段对话。
Pie Link 桌面热键扩展入口桌面唤起，任务交给浏览器里的 Pie 执行；与浏览器里是同一个会话。

不做：每页常驻悬浮球（遮内容、招反感）、双击 ⌘ 之类的自定义热键（受限页失效，容易和网站自己的快捷键冲突）。

Interaction

键盘、焦点与关闭

操作结果
↵发送。输入法组合中（isComposing）不提交，交给输入法选词。
⇧↵换行；输入框最多长到三行。
Esc关闭浮层，对话保留，焦点还给唤起前的元素。任务进行中不打断，胶囊继续显示进度。
⌘↵转到侧栏继续，同一个会话，浮层关闭。
⌘K新对话，与侧栏一致。
⌘⇧K唤起 / 关闭浮层；任务进行中也生效。
Tab焦点在浮层内循环：输入框 → 标签 → 消息里的按钮 → 标题栏按钮。
  • 点浮层外：关闭浮层，对话保留；正在跑的任务不中断，胶囊接管。
  • 打开时焦点直接进输入框；关闭时焦点还给原来的元素，页面不跳动。
  • 回答生成中：输入框暂时不可发送，思考行上有「停止」；停止后已发出的问题保留在对话里。
  • 任务跟随标签页：Pie 切到别的标签页，胶囊也跟过去；页面跳转后向后台查「这个标签页有没有任务」，有就重新挂上。
  • 浮层在扩展自己的 iframe 里渲染：网页脚本读不到对话内容，网页样式也影响不到它。

Edges

降级与边界

受限页面
chrome://、新标签页、Web Store、PDF 放不进浮层。同一个快捷键改为打开侧栏，并在顶部说明原因，不做成报错。
原文已经变化
替换前核对页面上的原文；用户自己改过或页面刷新过，就不替换，按钮降级为「复制」。
只读选区被要求改写
模型拿不到 propose_rewrite，只回一段文字，对比卡也不会出现「替换原文」，只给「复制」。这就是「改写」只在可编辑区域可用的原因。
长对话
超过 6 轮折叠较早的轮次；浮层内部滚动，标题栏和输入框始终可见。用户往上翻时，新消息不抢滚动，底部出现「↓ 新消息」。
选区下方放不下
下方空间不足 280px 时改到顶部居中，并在第一条消息里引用原文，保证不看页面也知道在改哪段。
首次使用
浮层第一次打开时，底部提示行显示一次「⌘⇧K 随时唤起」，用过后不再出现。
模型未配置
在对话里直接给出错误和「去设置」，不静默失败；已输入的内容保留，配好后可以重发。
站点拦截操作
横幅遮挡、跨域 iframe、Canvas 编辑器等导致操作失败时进入失败态：一句话说清原因，页面上标出卡住的位置，给「重试」和「在侧栏处理」。
多窗口 / 多账号
浮层只作用于当前窗口的标签页；唤起时就固定目标标签页，不跨窗口漂移。
Pie 自己
页面读取与定位工具跳过浮层和胶囊；截图前先隐藏它们，避免 Pie 看到或点到自己。

# v1.4.9 — Conversations no longer lock themselves after a reply

## The chat box going grey after the first message

Some conversations died the moment they started. You sent a message, Pie answered, and then the chat box turned grey, the send button stopped responding, and the conversation picked up a ✕ in the history sidebar. Nothing you could do in the panel brought it back — the only way forward was to start a new conversation and hope it didn't happen again.

This came from how Pie decides whether a task was interrupted. When the service worker goes idle or the panel reloads, Pie looks at any conversation still flagged as running and marks it as failed, on the assumption that it was cut off mid-task. That check is right for a task that really was interrupted. It was wrong here: when Pie answers in plain text — no clicking, no reading a page, just a reply — the flag that says "still running" was being cleared without waiting for the write to land. Go idle in that window and Pie would mark a conversation that had already finished successfully as failed, and a failed conversation can't be reopened.

Two things changed. Pie now waits for that flag to be cleared before it lets itself go idle, and the interruption check skips any conversation that already has a reply in it. A conversation that answered you is never treated as one that was cut off.

If you hit this, existing conversations marked ✕ stay that way — the flag is already written. New ones won't get stuck.

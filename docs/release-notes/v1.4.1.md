# v1.4.1 — Stopping a reply no longer locks the chat

A fix for a v1.4.0 regression.

## Fixes

- **Stopping a reply no longer bricks the session.** In 1.4.0, if you sent a message and hit Stop before the first step finished — or cancelled a streaming text reply — reopening the side panel marked that session as failed and locked the composer. You could not type or start another turn. Stop left an internal "task is running" flag set, so recovery treated the session as a crashed first step. That flag is now cleared. Sessions already marked failed by this bug stay failed; start a new one.

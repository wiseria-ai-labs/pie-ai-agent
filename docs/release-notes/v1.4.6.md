# v1.4.6 — Pie Link stops stealing its own socket

A follow-up to v1.4.5, which shipped the tray and update fixes but missed this one.

## Only one background service, for real this time

Pie Link's background service was supposed to allow only one copy of itself at a time. On macOS that guard never worked: a second copy would quietly take over the connection point and leave the first one running but unreachable — still attached to whatever was already talking to it, invisible to everything new. The symptoms were confusing: the tray reporting "not running" while a service was plainly alive, an extension talking to a version you thought you had replaced, or an update that appeared to succeed but changed nothing.

The service now checks whether someone is already listening before it claims the connection point. If a live copy answers, the new one steps aside. If it finds only a leftover file from a crashed run, it clears it and takes over.

## Pie Link 0.4.6

Update from the tray → Check for updates. This one does reach macOS through the in-place updater — it is a fix in the background service itself, not in the Pie Link app.

Everything from v1.4.5 is included: one tray icon instead of two after an install, a real **Update now** button in the *Check for updates* dialog, and progress while an update runs on both platforms. Those three still arrive with the installer package rather than the in-place updater, so grab the latest `.pkg` on macOS if you want them.

# v1.5.0 — 深度研究

## 一个问题，一份带引用的报告

有些问题塞不进一轮对话。"这五家供应商里谁真过了 SOC 2 Type II，用了半年的客户怎么说？"——这是一下午的开标签页，不是一句回答。深度研究就是让 Pie 替你过完这一下午。

你给它一个问题，另外可以补一句"重点看什么、跳过什么"，然后它离开大约十分钟。它先把问题拆成几个值得分头去查的方向，接着开始读：几十个来源，顺着读出来的缺口继续找，而不是照着一张固定清单走。最后写成一份报告，每一条论断都挂着编号引用，末尾附完整来源列表。

整个过程跑在我们的服务器上，不在你的浏览器里。你可以关掉侧栏、关掉标签页、去干别的。跑完 Pie 会发通知，点一下就打开那份报告。

## 看着它干活

研究页有一条随进度往下长的时间轴。你能看到它定下的子问题、当前在跑哪一个、每个方向查到了多少来源，以及刚刚读过什么的滚动列表。某个方向如果是死胡同，它会直说，而不是悄悄丢掉。

写完的报告有两个去处：**发送到对话**把它塞进输入框当草稿，你可以接着往下做；**下载 .md** 存成文件。报告语言跟随你的界面语言。

## 在哪儿用

侧栏里与对话、设置并列多了一个**研究**入口。输入框也有**深度研究**快捷入口——点它，你已经打的字会一起带过去。

深度研究属于 Pie 会员：每周三次，全部模型都包含在内。同一时间只能跑一个，不想要了可以取消。如果是我们这边出故障失败的，那一次不算进你这周的额度。

还没订阅？研究页上放了三份我们完整真跑出来的报告，可以先读实际产出再决定。

## 这一版还有

**模型在服务端自己跑的工具，现在能看见了。** 当供应商在它那侧执行工具时——OpenRouter 的网页搜索、网关的 MCP 调用——Pie 以前会被结果绊住。这类调用现在在侧栏里渲染成只读的远程步骤，带一个 ↗ 标记，不再被塞回 Pie 自己的工具循环里报错。

**Pie Link 现在整个都会自更新。** 菜单栏 app 以前会一直停在安装包给的那个版本，哪怕后台服务已经自己更新过了。两半现在一起更新——不用再为了追上版本重装一次 `.pkg`。

零碎修复：研究列表里的时间显示正常了、完成通知有了翻译、只有真正的 `http(s)` 链接才会变成可点的引用。

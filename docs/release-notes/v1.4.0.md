# v1.4.0 — Pie Link on Windows, updates itself, and simpler local-agent handoff

Pie Link is no longer Mac-only. Windows gets a real companion, both platforms can update without a privileged reinstall, and handing a task to Claude / Codex / Cursor is one brand instead of two rows.

## Pie Link on Windows

The Windows installer ships a tray app, a Start-menu shortcut, and the same local capabilities Pie Link already had on Mac:

- **Hand off to local agents** — Claude, Codex, Cursor, OpenCode, and Pi. Apps are detected from the registry and the Microsoft Store; terminal CLIs are found even when they live off the default PATH.
- **Skill scripts run on your machine** — on Windows they run as you, with an explicit warning that there is no sandbox on this platform. macOS still sandboxes by default.
- **Diagnostics in the tray** — Diagnostics and Repair Sandbox, plus a doctor that understands Windows (including localized registry output).
- **One instance, branded icon**, and upgrades that can roll back if something goes wrong.
- **Works with the Edge store build.** Pie Link now allowlists the Edge Add-ons extension ID, so connecting from a store-installed Edge copy actually launches the host. If you installed Pie Link before this release, reinstall once so the new origin is registered.

## Pie Link updates itself

You should not need a privileged reinstall for every daemon bump.

- **macOS** — the real binary now lives in `~/.pie/bin`. Checking for an update downloads a signed build and swaps it in. No password.
- **Windows** — the tray's "Check for updates" downloads the new installer (one UAC prompt).
- **If you installed Pie Link with 1.3.x**, install this release's package once. That puts you on the self-update track; later versions should not ask you to reinstall.

## Local agents, by brand

Settings used to list every form separately — Claude App, Claude Terminal, Codex App… eight rows for five products. That's gone.

- **One row per brand.** If either the app or the terminal is installed, the brand is available.
- **The confirm card picks the form.** Choose the brand first; if both forms are installed you pick App or Terminal (App is the default).
- **Apps open with the folder and a draft prompt already filled in** — Claude and Codex use their official deep links; Cursor opens the folder, then the prompt. You look, then you send. Terminal handoff still starts running on its own.

## Skill scripts, simpler to approve

Running a skill script no longer pops a capability list of domains and paths. You get the same kind of confirm you already know: skill name, what it does, the command and its arguments. Approve once per skill in a session.

Scripts can also run as long as they need — the old 60-second cutoff is gone. Progress shows while they run, and Stop kills the process.

## Custom providers

- **Responses or Chat Completions** — pick the wire your gateway actually speaks. Needed for GPT‑5.x-class models that reject tools on `/v1/chat/completions`.
- **Edit and delete models** on a custom provider. That used to be stuck after you added them.

## Also in this release

- File cards preview the first lines before you save. The button is now **Save**, which is what the dialog always did.
- A proxy that fails mid-stream no longer looks like a successful empty reply (and still billed you).
- If the first step of a task is waiting on a confirm card and the panel or service worker dies, the session is marked failed so you can start again — it used to stay "active" with no Resume.
